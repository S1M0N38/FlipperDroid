# FlipperDroid 2.1.0 — Quality, defect and opportunity audit

Date: 2026-11-03 · Audited branch: `claude/happy-franklin-wjei0n` (HEAD `1a745d4`) · ~20,300 lines of Kotlin, 48 screens, 32 ViewModels.

## 1. Executive summary

The project is functionally ambitious and well organized (MVVM + Compose, testable pure core, "capability honesty" principle), but the audit found **structural problems that affect every user** (distribution, crash on Android 7, dependencies) and **several modules that promise what they don't do** (traceroute, BLE fuzzer, NFC relay, MQTT/CoAP scanner, sniffer). There are also **security/privacy defects** (shell injection via `su`, TOTP secrets and card data in plaintext with backup enabled, captured credentials going to logcat and exposed over HTTP on the LAN) and **real protocol bugs** (Sony/RC5 IR bursts with inverted polarity, ONVIF blocked by cleartext, stuck key in BadUSB).

## 2. Methodology and what was verified

- Full read of the code (me: BLE, core, build/CI; three parallel reviewers: NFC/EMV, Wi-Fi/Network/Cameras, IR/BadUSB/Utilities). Every high-impact finding from the reviewers was re-checked by me in the code before being included here. Uncertain items are marked **(possible)**.
- There is no Android SDK in the environment (download blocked). I compiled the **pure core** (`camera/OnvifTools`, `flipper/*`, `infrared/*`, `security/TotpGenerator`, `reports/ReportGenerator`, `redteam/FuzzPayload`, `iot/IotProtocolScanner`, `network/PacketSniffer`, `util/AppLog`) with kotlinc 2.0.21 and ran `LogicUnitTest` with JUnit 4.13.2: **38/38 tests pass**. Four tests were excluded because they depend on Android classes (`ducky_keycodes`, `wifi_frequency_to_channel`, `skimmer_flags_hc05`, `mifare_hex_roundtrip`).
- The tests passing does **not** cover the bugs below: several asserts only check array size (e.g. `ir_burst_*`, `ir_necext_*`, `ac_*`), and that is why bug #7 passes the tests.

## 3. Defects by area

Paths relative to `src/main/java/com/example/flipperdroid/`.

### 3.1 Build, CI, manifest and distribution

- **[Critical] `java.time` without desugaring** (`build.gradle.kts` has no `isCoreLibraryDesugaringEnabled`). `NoClassDefFoundError` is an `Error`, not an `Exception`: the `catch (e: Exception)` blocks don't hold it. Fix: `coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.x")` or `SimpleDateFormat` as `AppLog` already does.
- **[Critical] Release = debug APK** (`isMinifyEnabled=false`, no `signingConfig`, CI runs only `assembleDebug`). Fix: release keystore via secrets (`ANDROID_KEYSTORE_BASE64`…), `assembleRelease`, R8 enabled (will need keep rules for zxing/journeyapps).
- **[High] Workflow reuses the `v2.0.0` tag on every push to `main`** (`build.yml:58-73`) while the app is 2.1.0; global `permissions: contents: write`; "Android 10+" text contradicts `minSdk 24`. Fix: remove the step and publish only by tag.
- **[Medium] Inconsistent dependencies**: Compose BOM 2024.09.00 (Compose 1.7) + pinned `material-icons 1.6.4`; lifecycle 2.6.1 in the catalog vs 2.8.7 inline; `navigation-compose 2.8.9` + `navigation-runtime-android 2.9.0-alpha08` (alpha in production); `core-ktx 1.10.1`; `navigation-runtime-desktop` never used; `kotlin("plugin.serialization")` applied without any use; `kotlinOptions` deprecated.
- **[Medium] Manifest**: `USB_PERMISSION` is not a real permission; duplicated `ACCESS_NETWORK_STATE`; `READ/WRITE_EXTERNAL_STORAGE` without `maxSdkVersion` (nothing uses shared storage); `<uses-feature android.hardware.usb.host />` without `required="false"` (Play hides the app on devices without USB host); `allowBackup=true` with empty `backup_rules.xml`/`data_extraction_rules.xml`; `NDEF_DISCOVERED` with `mimeType="*/*"` puts the app in the chooser for **every** NDEF tag on the system; `ACTION_USB_DEVICE_ATTACHED` is handled in `onNewIntent` (`Main.kt:143`) but there is no matching intent-filter and no `requestPermission` → the legacy BadUSB path is unreachable.
- **[Medium] `as BluetoothManager/WifiManager/UsbManager` casts** without `as?` in `Main.kt:146`, `BluetoothViewModel.kt:113` (called in `onCreate` → crash on open in an emulator/device without Bluetooth), `SkimmerDetectorViewModel.kt:94`, `HidKeyboardViewModel.kt:89`, `WifiAnalyzer/Deauther/Wardriving/EvilPortal`.
- **[Medium] `AboutScreen.kt:85` shows "Version 1.0.0"** (actual: 2.1.0). Use `packageManager.getPackageInfo(...).versionName` or `buildFeatures { buildConfig = true }`.
- **[Low] NFC foreground dispatch**: `techListsArray = arrayOf(arrayOf(NfcA, NfcB, NfcF, NfcV))` is an AND list (the tag would have to support all 4) — it only works because `TAG_DISCOVERED` is in the filter. Consider `enableReaderMode`, which also eliminates the "stale" intent (§3.2).
- **[Low] Outdated docs**: CHANGELOG without 2.1.0; ROADMAP mentions an SDK in `/home/archiznoo`; the agent instructions then in `CLAUDE.md` (now [`CONTEXT.md`](CONTEXT.md)) didn't list ~15 modules (Bluetooth Classic, LAN Discovery, Netcat, GPS Spoof, Crypto Tools, Wi-Fi QR, Default Creds, Tracker Detector, NDEF Emulator, Card Emulation, red team); `.github/release-v2.0.0.txt` and `assets/logs/exemple.log` are committed junk; `ANDROID_CAPABILITIES.md:22` marks "Relay NFC/HCE" as available.
- **[Low] i18n**: 376 hardcoded `Text("…")`, `strings.xml` with 2 entries, UI mixes PT/FR/EN (e.g. NFC logs in French, "Retour" in BLE Spam).

### 3.2 NFC / EMV / Flipper

- **[High] NFC relay is a misleading stub**: `nfc/NfcRelayAttack.kt` only builds a fixed command list with empty responses and tries to open a socket to `127.0.0.1:6669` (nothing listens); `NfcRelayAttackViewModel.captureRelayAttack/replayCapture/exportCaptures` have **no callers at all** (Main.kt only routes tags to `NfcViewModel` and `EmvReaderViewModel`); the screen says "Scan an NFC card to capture" but that never happens. Recommendation: remove the module (and the ANDROID_CAPABILITIES line) or rename it honestly to "APDU probe" using `ApduCapture`, which already exists and works.
- **[High] Card data in plaintext + backup**: `EmulationStore` stores the READ RECORD responses (which typically include PAN/track 2/name) in `hce_emulation`. Fix: exclude from backup, mask 5A/57/5F20 and encrypt with a Keystore key. `EmvCardData.toString()` (`EmvCardReader.kt:349-356`) prints the full PAN (latent leak).
- **[High] Ultralight/NTAG clone writes config/lock/PWD/PACK** (`MifareUltralightUtils.kt:52-58` only skips pages 0–3). It can lock the target card irreversibly. Fix: identify the type via `GET_VERSION` and skip the configuration range (NTAG213 40–44, 215 130–134, 216 226–230); writing those pages only with an explicit opt-in.
- **[High] Two simultaneous connections to the same Type-4 tag**: `NfcViewModel.onTagScanned` opens `Ndef.connect()` on IO while `Main.kt:174` triggers `EmvReaderViewModel.readCard` → `IsoDep.connect()` on the same `Tag` (the comment in `NfcViewModel.kt:91-93` itself explains why this fails). Fix: a single coordinator per tag (Mutex) and route to EMV only IsoDep tags.
- **[Medium] "Stale" NFC intent**: `Main.kt:126` calls `handleNfcIntent(intent)` in `onCreate` without checking `savedInstanceState`. When the app is launched by the system from a tag (manifest filter), every rotation reprocesses the tag; with a clone armed, `performClone` runs again. Fix: process only when `savedInstanceState == null` and then `setIntent(Intent())`.
- **[Medium] Clone can run twice** (the `_cloneArmed` flag is only cleared after the write; `pendingCloneDump` is a non-volatile `var` read/written on different threads).
- **[Medium] Partial dump becomes a result**: with no per-sector `try`, one `TagLostException` leaves `dump` misaligned and it is saved to history/`.nfc`/MCT with shifted sectors (`NfcViewModel.kt:96-151`, `287-293`).
- **[Medium] `Ndef.close()` outside `finally`** (`NfcViewModel.kt:175-178`, `219-229`).
- **[Medium] Incorrect `.nfc` export**: `FlipperNfc.generate` always writes `Device type: Mifare Classic`, `ATQA 00 04`, `SAK 08` (4K should be `18`; Ultralight/NTAG/NfcV become "Mifare Classic"), and unknown blocks are emitted as `-- -- --` instead of `??` (the Flipper won't load them) **(possible, check against the firmware)**. `NfcInfo` already has the real ATQA/SAK — use them.
- **[Medium] `ApduCapture`** keys responses only by command → collision between AIDs; stores GPO even on error (`6985`). The EMV reader ignores `61xx/6Cxx`; brute-force fallback of 100 READ RECORD per AID; `transceive` swallows `IOException` and keeps polling a card that has already left the field.
- **[Medium] `emv_card_service.xml` registers the Visa AID in the `payment` category** with a service that responds `9000` without FCI: if the user picks the app as the default payment app, Visa taps go to a stub. Remove the `payment` group.
- **[Medium] `EmvReaderViewModel.readCard`** is called for every tag (Mifare/NTAG) and shows "No EMV data" + stale data (it doesn't clear `_cardData`).
- **[Low]** `NdefHceService` accepts any AID in `00 A4 04`, imprecise status words; `NdefHceViewModel` doesn't validate size ≤ 1022 (CC advertises 0x0400); UTF-16 NDEF text decoded as UTF-8; `exportMct` labels 4K sectors wrong; `exportBin` zeroes unreadable blocks; `importMct/importBin` take the UID from `blocks[0].take(8)` (wrong for a 7-byte UID); hex helpers duplicated in 3 files; `MifareClassicUtils.readSector/writeBlock` and `NfcVUtils.writeBlock` with no callers; `hexToBytes` calls `android.util.Log` (breaks JVM tests that hit the catch); `FlipperFilesScreen` parses a large `.sub` on the main thread; no warning when NFC is off.

### 3.3 Bluetooth / BLE

- **[High] `BleSpamScreen` broken on Android 8–11**: annotated `@RequiresApi(S)` but navigable on any version; requests `BLUETOOTH_ADVERTISE/SCAN/CONNECT` unconditionally → on API < 31 the system returns "denied" and the screen stays stuck on "Bluetooth permissions are required". The other BLE screens already build the list per version — copy that.
- **[High, likely] Extended advertising kills effectiveness**: `ModernAdvertisementService.prepareAdvertisementSet` forces `legacyMode=false` whenever the chip supports it (Pixel 7 does). Swift Pair is defined over legacy ADV_IND and Windows only receives extended advertising with an opt-in (`AllowExtendedAdvertisements` is `false` by default — [Microsoft Learn](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.advertisement.bluetoothleadvertisementwatcher.allowextendedadvertisements?view=winrt-26100), [publisher](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.advertisement.bluetoothleadvertisementpublisher.useextendedadvertisement?view=winrt-26100)); iOS/Android also scan legacy for Continuity/Fast Pair ([Novelbits](https://novelbits.io/bluetooth-low-energy-advertisements-part-2/)). Needs a field test; alternative: keep legacy for payloads ≤ 31 bytes and only use extended when it doesn't fit, with a warning.
- **[Medium] Silenced errors**: `onAdvertisingDataSet(status)` is ignored → `updateAdvertisement()` returns `true` even when the controller rejects (payload > 31 bytes in a legacy set, switching between a set with/without scan response in "ALL" mode); SwiftPair with long names ("Microsoft Bluetooth Mouse", "Surface Ergonomic Keyboard") exceeds 31 bytes in legacy.
- **[Medium] `BleSpamViewModel` with no `onCleared()`** → the Handler keeps emitting after the Activity dies.
- **[High] GATT Fuzzer**: the screen fuzzes the **first paired device** (`bondedDevices.firstOrNull()`, `!!` on the adapter) with no selection (`selectedDevice` never used; `device.name` without try/catch → `SecurityException` without `BLUETOOTH_CONNECT`); the VM writes in a loop with `delay(100)` without waiting for `onCharacteristicWrite` (the stack accepts only 1 pending operation → most are dropped but logged as "Wrote"); `_fuzzResults`/`BleGattFuzzResult`/`severity` are never populated — the CHANGELOG's "real-time vulnerability detection" does not exist; 512/1000-byte payloads exceed the ATT maximum without MTU negotiation; `viewModel { BleGattFuzzerViewModel(context) }` receives the Activity context (leak); `gatt.close()` is not called at the end.
- **[Medium] Scanner (`BluetoothViewModel`)**: on API 24–30 `checkPermissions` only looks at `BLUETOOTH/BLUETOOTH_ADMIN` (normal) and reports "granted" without location → silently empty scan; GATT reads/notifications with no queue (2 clicks = 1 lost); `writeCharacteristic` status ignored on API 33+.
- **[Low]** `AdvertisementSetQueueHandler`: `_active/advertiseNext/_callbacks/_advertisementQueueMode` dead, `% size` unguarded; `AdvertisementSet.validate/build` and `AdvertiseData.validate` are stubs; `HidKeyboardViewModel` creates `newCachedThreadPool()` on every registration and uses the Activity context in `getProfileProxy`; `TrackerDetector` marks any 0x0075 manufacturer as "Samsung (SmartTag?)" (every Samsung phone/watch); `SkimmerDetector` OUI `"20:16:"` incomplete and the name `"csr"` matches any headset with a CSR chip; `BluetoothClassicViewModel.hexToBytes` accepts invalid digits.

### 3.4 Wi-Fi, network and IP cameras

- **[Critical] Injection in `su -c`**: `NetworkToolsViewModel.kt:469` concatenates `host` and `parameters` without validation (`1.1.1.1; reboot` runs as root); `PacketSniffer.kt:52-61` concatenates the BPF filter and interface (also breaks legitimate filters containing parentheses). Fix: a single `RootShell` helper with argv quoting, timeout, separate stderr, exit code and `pkill` of the child process.
- **[High] ONVIF blocked by cleartext** (`IpCameraViewModel.kt:336-360` uses `HttpURLConnection` over `http://`; no `usesCleartextTraffic`/`networkSecurityConfig`). Fix: `res/xml/network_security_config.xml` with `cleartextTrafficPermitted="true"` (you can't restrict by CIDR; document it).
- **[High] WS-Discovery with the wrong namespace**: `OnvifTools.kt:56` uses `xmlns:dn="…/ver10/device/wsdl"` for `dn:NetworkVideoTransmitter`; the spec uses `…/ver10/network/wsdl` — conformant cameras may ignore the probe. The existing test only checks `contains("NetworkVideoTransmitter")`.
- **[High] Netcat HTTP** exposes the root of the app's external directory without auth on 0.0.0.0; `readBytes()` of a large file → OOM kills the process; the path check accepts sibling directories (`startsWith` without a separator); HTML listing without escaping.
- **[High] Evil Portal**: `CharArray(contentLength)` sized from a client header (OOM → uncaught `Error` → kills the app); single-threaded server without `soTimeout` (one silent client blocks everything); captured credentials go to `AppLog` → logcat + log export in `getExternalFilesDir("logs")` (served by Netcat); race on stop/start leaves port 8080 stuck; server failure is overwritten by "Hotspot up"; the hotspot's `onStopped` is not handled; listens on all interfaces; gateway `192.168.49.1` hardcoded.
- **[High] Fabricated results**: "traceroute" is only a TCP connect on fixed ports labelling the **local** address as a hop (`:385`) and reports `127.0.0.1 [ACCESSIBLE]` on any exception (`:355-357`); MQTT topic scan returns the `topics` list that is never populated (`IotProtocolScanner.kt:140-182`); CoAP appends the path as raw bytes without a Uri-Path option and counts any response as "found"; the sniffer parses `tcpdump -A` and picks up `source="IP"`, counting payload lines as packets; tcpdump missing → "Capture complete: 0 packets" (stderr/exit code ignored; tcpdump isn't even bundled); deauth logs "burst sent" ignoring the exit code and the watchdog kills only the `su` wrapper, not `mdk4`.
- **[High] nmap**: the 30 s timeout is dead code (`waitFor()` without a timeout, `:503-516`); it re-copies 11 MB of assets on every scan; `chmod -R 755 /data/local/tmp` changes files from other apps; a copy error becomes "nmap binary not found"; on a device without root a missing `su` is reported as "binary not found"; fixed DNS 8.8.8.8; **(possible)** `nmap-services`/`nmap-service-probes`/`nmap-os-db` are missing from the assets → empty `-sV/-O`; the Nmap license restricts redistribution — check it.
- **[Medium]** Port scan 1–65535 with no cap/cancel (~7 h on filtered ports); `isReachable` is not ICMP without privileges; `/proc/net/arp` restricted since Android 10 **(possible)** → empty table with no warning; `setWifiEnabled` is a no-op on API 29+; `WifiDeautherViewModel.kt:131` holds the **Activity** context (leak, the VM lives in the Activity); `WifiDeautherScreen` annotated `@RequiresApi(S)` with no guard → NewApi lint error; 6 GHz becomes "5 GHz" with channel 0 (3 copies of `frequencyToChannel`); MAC spoof leaves the interface down if `ip link set address` fails; wardriving overwrites `firstSeen` and iterates a `LinkedHashMap` from another thread during export (CME); IoT "Stop" doesn't cancel the job; the range parser accepts `a.b.c.0/24` as a literal string; GPS spoof accepts invalid coordinates and only affects the platform provider (not Fused); PTZ `ContinuousMove` with no timeout/auto-stop when leaving the screen; RTSP "OPEN (no auth)" inferred from OPTIONS alone; `NEARBY_WIFI_DEVICES` with `neverForLocation` may filter SSID/BSSID on Android 13+ **(possible)**; WPA3 detection only by the literal "WPA3" (SAE/OWE fall back to WPA2/OPEN).
- **[Low]** `_results.value = _results.value + …` without `update{}` in several VMs; incomplete CSV quoting in Wigle/sniffer; sockets not closed in `finally` (traceroute, SSDP, WS-Discovery); banner grab sends plain HTTP on 443; NSD deprecated in 34; `soapFaultReason` gives a false positive on any text containing "Fault" and loses `<Text xml:lang>`.

### 3.5 Infrared and air conditioning

- **[High] Burst polarity** (`IrProtocols.encodePowerBurst`): the gap is `out.add(gapUs)` as an extra element, assuming the frame ends in a mark. SIRC **always** ends in a space (`sirc()` ends with `600`), and RC5 ends in a space when the last bit is 0 → the gap becomes a mark and the repetitions come out inverted. Affects Sony in TV-B-Gone/`PowerCodes` and Philips RC5 power; same risk in `raw` bursts with an even count (`IrFile.kt:37-40`). Fix: if `frame.size % 2 == 0`, add the gap to the last element. Test: assert mark/space alternation on every burst.
- **[High] "Sent" without an emitter**: `irManager?.transmit()` is a no-op when `irManager == null` and the status says "Sent" (`IrRemoteViewModel.kt:110-112`, `IrToolsViewModel.kt:68-72,145-150`, `AcControlViewModel.kt:33-35`). Check `hasIrEmitter()` and report failure.
- **[High] IrRemote's power sweep** doesn't deduplicate (LG and TCL both use NEC 04/08 → the same toggle 2× = cancels) and picks up Epson's `Power_on`+`Power_off`; it sends isolated frames that the code itself documents as "filtered out as noise".
- **[Medium] AC**: swing offered for all brands but ignored by LG/Coolix/Midea/Samsung; Midea `MODE_FAN → 0x4` (= DRY), Coolix FAN falls through to AUTO; the Samsung checksum is a self-declared "approximation" with no UI warning; the "Gree VALIDATED" label rests on a test that only checks size.
- **[Medium]** `IrFile.parseRaw` silently drops invalid tokens (shifting mark/space pairs) and accepts 0/negatives; brute-force with an unknown protocol emits nothing but shows progress; `addressHex.toIntOrNull(16) ?: 0` turns "0x04" into 0; importing an IRDB folder parses everything on the main thread (ANR); hold-to-repeat buttons with `onClick = {}` (unreachable via TalkBack); race on `_running` (2 taps = 2 sweeps).
- **[Low]** RC6X aliased to RC6 mode 0; NEC address truncated to 8 bits; RC5 toggle fixed at 0; the Apple encoder ignores the `.ir` address field; `AC_Coolix.ir` "Turbo" and "Led" with the same command; `AcProtocols` duplicates Coolix from `IrProtocols`.

### 3.6 BadUSB

- **[High] Legacy BadUSB (USB host) cannot inject keystrokes**: it writes HID reports via `bulkTransfer` to an OUT endpoint of a connected HID device — the phone is the host, not the keyboard. The UI says "Connected as USB Keyboard" and "Ready to execute keyboard commands"; `bulkTransfer` and `claimInterface` results are ignored; `isUsbHostAvailable = usbManager != null` doesn't test `FEATURE_USB_HOST`; and the path is unreachable (see manifest). Recommendation: remove it or label it as an experiment.
- **[High] Root gadget — stuck key**: `sendKey` does press → `delay(5)` → release; `stop()` cancels during the delay and the `finally` (`:75-81`) never sends the zero report → Shift/Ctrl/GUI stay pressed on the PC. Fix: release in `withContext(NonCancellable)`.
- **[High] Combos lose keys**: only `"DELETE"` is recognized in a combo (`CTRL ALT DEL` sends only CTRL+ALT); tokens with `length != 1` (`ALT F4`, `CTRL ESC`, `ALT LEFT`) send only the modifier (`:157-168`). Fix: a single table of key names.
- **[Medium]** `catch (e: Exception)` swallows `CancellationException` (stop becomes "Error"); `DEFAULT_DELAY` applied to `REM`; unknown commands (REPEAT, HOLD, MOUSE) ignored but "Script finished"; non-US characters dropped; `su` stderr never drained **(possible hang)**; `RootBadUsbScreen` says "802.11-style keystroke injection"; two diverging `charToKeycode` tables (the legacy one loses `[ ] \ { } ~`).

### 3.7 TOTP, cryptography, reports, settings

- **[High] TOTP**: `otpauth://` ignores `algorithm/digits/period` (`TotpViewModel.kt:59-60`) and `TotpGenerator` only does HmacSHA1 → SHA-256/512, 8-digit or 60 s accounts generate wrong codes with no warning; secrets in plaintext + backup (see §1); `init { load() }` without try/catch (corrupted JSON = screen crash); invalid Base32 is silently "cleaned" (`0,1,8,9` disappear); HOTP is announced in the KDoc but doesn't exist; the label is not URL-decoded; no `FLAG_SECURE` (codes/passwords show up in screenshots and in recents).
- **[Medium] Password Generator** generates the password QR during composition with 262 k× `setPixel` on the main thread; clipboard without `EXTRA_IS_SENSITIVE`; no feedback when no character class is selected.
- **[Medium] Report Generator**: Markdown isn't escaped (evidence containing ``` closes the block); duplicated IDs after removal (`FINDING-${size+1}`); timeline with `- - `; JSON/HTML omit the timeline; `average()` of an empty list → NaN displayed; `java.time` (see §1).
- **[Medium] Settings**: keep-screen-on is only applied while the Settings screen is composed and `onDispose { }` is empty (it is not applied at launch, nor cleared on exit); `notifications/vibration/sound` are persisted and never read; the KDoc describes cache clearing/export that don't exist.
- **[Low] CryptoTools**: `isDigit()` accepts non-ASCII digits; Base64/hex binary output shown as U+FFFD; HMAC only with a UTF-8 key; `String.format` per byte. `QrScannerScreen` opens a URI without confirmation and loses the result on rotation. `colors.xml` with `red_*` alpha 00 (template). A light parent theme can flash white in dark mode **(possible)**.

### 3.8 Tests

- `ExampleUnitTest` (`2+2`) and `ExampleInstrumentedTest` (commented out) are placeholders.
- Weak asserts: `ir_necext_uses_inverted_command`, `ir_rc5x_*`, `ac_*`, `ir_burst_*` (they assert the buggy layout), TOTP SHA-1 only, ONVIF probe without checking the namespace.

## 4. Improvement opportunities and new implementations

### 4.1 Foundations (highest return on effort)
1. **A real release pipeline**: keystore signing via secrets, `assembleRelease` + R8, mandatory `lint` and `testDebugUnitTest` on PRs, release only by tag, `versionCode` derived from the tag, F-Droid metadata (`fastlane/metadata`), ktlint/detekt.
2. **Desugaring** (or a documented `minSdk 26`) and a single, current version catalog (Compose BOM 2025.x, lifecycle 2.9, stable navigation 2.9, core-ktx 1.16).

### 4.2 Per module — interesting implementations feasible on Android
- **NFC**: `GET_VERSION` to identify NTAG213/215/216 and the real capacity; `PWD_AUTH` with a supplied password to read protected pages; import key dictionaries in the Flipper format (`mf_classic_dict`) and cache keys per sector; DESFire `GetVersion` (read-only); NDEF with Smart Poster/MIME/UTF-16 and multiple records; `UPDATE BINARY` in the Type-4 emulator (emulated tag writable by a reader); extra read-only EMV (ATC, PIN try counter, transaction log via `GET DATA`), handling of `61xx/6Cxx`; `.nfc` with real ATQA/SAK, `Page N:` layout for Ultralight and `??` for unknown; `enableReaderMode` instead of foreground dispatch.
- **BLE**: scanner with filters (name/UUID/RSSI), AD structure decoding (flags, iBeacon/Eddystone, service data), RSSI history, JSON/CSV export, standard service/characteristic names (assigned numbers), GATT operation queue + MTU; tracker detector with "presence time" despite MAC rotation, audible alert, Google Find My Device network; HID with mouse and DuckyScript over BLE reusing the gadget engine, keyboard layouts (ABNT2); Beacon with Eddystone-UID/TLM and AltBeacon; Bluetooth Classic with OBEX push and an RFCOMM server.
- **Wi-Fi/network**: an **ESP32 companion (Marauder/Evil-M5) over USB-serial or BLE** — the only realistic path for deauth/beacon/evil twin (already in ROADMAP); 6 GHz band and `getInformationElements()` for SAE/OWE; wardriving in a foreground service with WiGLE upload; a bundled OUI database to label BSSIDs/ARP/LAN; LAN discovery with NetBIOS (137), SNMP `sysDescr` with a supplied community, `Server:` parsing and TLS certificate capture; packet capture **without root via `VpnService`** (own-device traffic only, say so clearly) with pcap output; nmap with `--datadir`, `-oX` and a cancel button; Netcat with TLS/auth and a read-only mode; cameras with `GetSnapshotUri` + RTSP preview (Media3), DESCRIBE with Digest to validate credentials, Hikvision `/ISAPI` and Dahua `magicBox.cgi` probes, throttling in the audit.
- **IR**: import the whole Flipper-IRDB with search and favourites, Pronto Hex import, raw timing editor, macros, learning via an "external IR receiver" (honest: the phone has no RX).
- **BadUSB**: DuckyScript 3 (REPEAT, HOLD/RELEASE, MOUSE), explicit errors for unknown commands, a payload library, non-US layouts, mouse gadget.
- **Utilities**: HOTP and Steam Guard, biometric vault unlock; PDF reports (`PdfDocument`) with persistence; QR scanner with history; Crypto Tools with hex/Base64 keys and more encodings.
